# Scutio 量化线索入口设计

状态：设计草案，尚未实现或验证信号有效性。日期：2026-09-14。现状核对基于 `0d05d28`。

## 1. 定位与目标

为 [发现能力](discovery-design.md) 增加一个可重复计算的候选入口：在明确样本中，用统一口径识别值得调查的变化，再由 AI 核实原因、经济影响与价格条件。

本设计属于发现所使用的数据工具与方法，不新增第七个能力。量化计算回答「哪些记录呈现了某种变化」，发现与研究回答「这种变化是否构成值得考虑的投资机会」。原有产业、公告等发现入口继续使用，量化筛选不作为所有候选必须通过的门槛。

第一版只研究一个假说：**同一财年的盈利预期上修、而按该预测计算的参考 PE 下降的公司，是否能提供有价值的新增研究线索。** 这是一项待验证的假说，不预设其具有超额收益。

本轮交付设计文档，不实现策略、交易执行、组合优化、自动调仓或后台任务。研究增量实验与投资收益验证分别进行，后者依赖更严格的历史数据。

## 2. 第一轮实验范围

以执行时取得的中证 500 最新成分作为一个明确的 A 股样本，记录成分来源、源日期、抓取时间、完整证券身份和实际行数。源日期不明或样本不完整时披露缺口，不以指数名称推定已经取得 500 家有效公司。

当前 `breadth.index_constituents` 提供最新成分，没有历史时点参数；不能把当前成分用于过去的投资样本而声称不存在幸存者偏差。首轮可查询 `index_constituents('000905', include_weights=False)`，本实验不需要权重。

当前成分行主要提供 `code/exchange`，尚非统一 `symbol`。进入计算前依据证券类型与交易所信息确认完整身份，复用现有身份校验；无法确认的行单列，不按代码后缀猜配证券。

为本轮显式指定起点 `T0`、终点 `T1`、目标预测财年 `F` 和预测陈旧度阈值。例如从一个已完成交易日向前观察约三个月；实际边界在运行前冻结并统一映射到明确交易日，不按公司自行挑选有利窗口。

目标财年用绝对年份表示。同一轮跨年时仍比较同一个 `F`，不把「本年」「明年」滚动字段直接相减。观察窗口与用户投资期限分别记录，短期预期修订只能作为长期研究的入口。

样本与窗口是实验配置，不写成日常能力的固定市场、数量或时间限制。先检查数据可得性，再决定是否扩大样本；未取得数据的公司单列，不计为信号未命中。

## 3. 数据与时间口径

### 3.1 可复用的现有能力

| 当前入口 | 用途 | 现有边界 |
|---|---|---|
| `breadth.index_constituents` | 确定当前研究样本 | 最新成分，不能重建任意历史证券池 |
| `research.stock_reports` | 取得逐公司研报及预测原值、机构、日期与原文位置 | 供应商覆盖有限；列表展示日期可能不同于原文日期，历史值的版本也需核对 |
| `research.consensus_revisions(reports=...)` | 标准化同证券、同机构、同财年的 EPS 观测与相邻修订 | 不是固定窗口快照；不是供应商全市场一致预期；同日冲突需额外阻断 |
| `market.security_bars` | 取得近期日线及可得端点价格 | 主要按近期 `count` 获取，没有任意历史截止日参数；必须检查返回范围实际覆盖窗口。默认不复权，复权口径依源而异 |
| 原文与公司行动门面 | 查证预测依据、分红拆股及股本变化 | 按公司调用，不能将空响应直接视为确认没有公司行动 |
| `screen_records.py` | 对计算结果按明确条件筛选与展示 | 复用现有逻辑，不增加另一套阈值与排序工具 |

详细约定以 [研报与一致预期说明](../skills/scutio/references/toolkit/04-research.md)、[行情说明](../skills/scutio/references/toolkit/02-market.md) 和 [筛选说明](../skills/scutio/references/toolkit/screening.md) 为准。以上为代码审阅结果，本轮没有重新调用金融接口。

### 3.2 每条观测要能追溯什么

沿用现有信封及源字段，计算所需信息包括：

- 完整证券身份、机构身份、绝对预测财年、EPS 原值及币种/每股口径。
- 研报标识、原文位置、源展示日期；能查明时补充实际发布日期与时间。
- 数据抓取时间、版本或修订证据，以及上游分页、跳过、冲突和错误信息。
- 价格交易日、价格类型、币种、复权状态、数据来源与覆盖范围。

展示日期、报告期、抓取时间与信息首次可得时间分别保留。没有证据证明的字段留空，不把 `retrieved_at` 或供应商响应时间补成历史可得时间。

同机构的不同名称只有在确认身份相同时才合并。机构与作者数量分开；当前作者字段缺失不能伪装成完整分析师覆盖。

### 3.3 当前研究与历史验证分开

**当前研究模式**可以用今天取得的材料比较其标注的历史变化，输出标明「按当前可得材料回溯」。如果原始发布时间或版本不可确认，不声称这条信号在历史 `T1` 就能被投资者计算出来。

固定端点按日期选取的规则仍然执行；它在当前研究中只是基于已知材料的回溯约定。源缺少日期、日期存在冲突或被确认是截止日之后的预测，不得用于相应端点。

**历史投资验证**要求所有输入在决策时点已经公开且可使用，包括当时证券范围、预测原始版本、公司行动与价格。今天修订后的 EPS、后来补录的预测或当前成分，不能回填到过去。

只有披露日期而无时间时，历史验证采用事先固定的保守可用时点，例如确认发布日期后的下一交易日；不能在同日收盘决策中默认使用盘后资料。保守顺延也不能弥补版本和发布日期真实性的缺失。

第一版不承诺具备历史时点数据。数据不足时先完成当前研究增量实验；历史验证所需的快照或数据集另行评估。

## 4. 固定窗口的预测比较

### 4.1 按机构配对

以「证券、机构、预测财年」分组，分别选取在 `T0`、`T1` 边界允许使用的最后一条有效预测，得到 `E0`、`E1`。同时保留两条原始研报的实际日期，避免将整个观察窗口都说成机构刚刚发生的修订。

只统计两个端点都存在、口径可比且未超过本轮陈旧度阈值的机构。一个机构无论期间发了多少报告，在一个窗口内只贡献一次端点比较；同一预测延续到两端时可以记为未更新，但必须展示其年龄。

只有新端点的机构记为新增覆盖，只有旧端点或缺失的机构分别标注，均不作为上修或下修。两个端点有效覆盖的变化单独报告，不能把机构构成变化解释为盈利预期变化。

同一机构、同一财年、同日出现互相冲突的 EPS 且无可靠时间或版本顺序时，阻断该端点比较，不按列表顺序取一条，也不悄悄退到更旧的值。相同预测的重复转载去重，不放大覆盖数。

实现前需要修正或统一处理一个现有边界：`consensus_revisions` 对相邻修订的判断中，同日冲突的第一条仍可能与前一日形成方向。新入口不能直接把现有 `direction` 当作已经合格的窗口信号；共享的冲突校验应使所有受影响端点得到一致处理。

### 4.2 单机构计算

在币种、股数与盈利定义可比时，先保留绝对变化：

```text
eps_change = E1 - E0
```

只有 `E0`、`E1` 均为正数，且基数不落入本轮明确设置的近零区间时，计算：

```text
eps_change_pct = (E1 / E0 - 1) × 100
```

零值、负值及扭亏记录保留原始值与变化性质，不套正盈利增长率和常规 PE。接近零的基数容易放大比率；阈值按本轮币种、单位和数据精度预先说明，不为取得好看的结果事后调整。

不把「从亏损 1 元变为亏损 0.5 元」写成盈利增长负 50%，也不把跨年字段切换视为上修。

### 4.3 公司层面汇合

保留机构级记录，展示有效配对机构数、上修/下修/持平数、各机构预测日期和分歧。另标注窗口内没有新报告的机构；「未更新」可以与持平重叠，不作为第四类相加。公司层面可给出合格机构修订百分比的中位数，但名称必须是「已覆盖机构的配对修订中位数」，并说明分母与无效记录数。

只有一家机构时仍可保留研究线索，不能表达为广泛一致上修。披露上修家数必须同时展示下修、持平、未更新和覆盖范围；不把多篇同机构报告当作多票，也不把这些统计升级为全市场一致预期。

不同公司研报覆盖差异会影响入选机会。研究比较时保留该偏差，并通过其他发现入口和遗漏复查观察被忽略的对象。

## 5. 价格与估值计算

### 5.1 先对齐端点和每股口径

价格使用明确交易日、同一证券、同一币种的日线。窗口边界的交易日对所有候选一致；个股停牌或数据缺失导致没有端点价格时，保留缺口，不能暗中使用更早收盘价。

每个端点的 PE 使用该端点实际未复权股价与对应股数口径的预测 EPS。不能将前复权股价直接除以未经相同每股处理的 EPS，也不能把总回报序列当作实际可成交股价。

拆股、送转、配股、重大股本变化以及预测定义变化，可能同时影响价格和每股盈利的可比性。第一版遇到跨端点每股计量基准变化、需要重新换算的记录，保留原值并转交补证，不参加自动命中，也不直接比较原始 EPS 的修订方向。源没有说明每股口径时披露未知，先补查原文，不能默认已对齐。

本版本公式中的 `E0/E1` 均指原始端点 EPS，只用于已确认跨端点口径可比的记录，不实现拆股等自动换算。将来若支持换算，必须区分「用于修订比较的共同股数基准 EPS」与「匹配各端点实际股价的 EPS」。例如一拆二前 `P0=20、EPS0=2`，之后 `P1=11、EPS1=1.2`，不能把旧 EPS 调为 1 后仍拿旧股价 20 相除；该案例在第一版预期为待补证。

现金分红会机械影响除息后的未复权价格。PE 水平仍以各时点实际价格计算，价格变化同时标注分红影响；未能核验公司行动时，不将「涨幅低于盈利上修」直接解释为市场反应不足。若另外提供考虑分红的回报指标，需单列来源、算法和口径，不能混入 PE 公式。

### 5.2 合格记录的公式

用 `P0`、`P1` 表示两端实际未复权价格。输入须为有限数值，价格严格为正，不能把布尔值、无穷或缺失当作数值使用。在正盈利、同口径且无未解决每股调整问题时，对每个有效机构分别计算：

```text
price_change_pct = (P1 / P0 - 1) × 100
pe0 = P0 / E0
pe1 = P1 / E1
pe_change_pct = (pe1 / pe0 - 1) × 100
```

该 PE 是「按某机构、某财年预测计算的参考 PE」，不是 `valuation_snapshot` 的 TTM PE，也不是完整公司估值。

虚构示例：`E0=2`、`E1=2.4`，`P0=20`、`P1=22`，EPS 上修 20%，股价上涨 10%，参考 PE 从 10 降至约 9.17，变化约 -8.33%。这个结果只说明按该组预测计算的倍数变化，不能证明便宜或市场遗漏。

机构层面的 PE 变化可以汇合展示分布或中位数，但保留原始配对关系；不把不同机构集合的均值拼成虚假的一致预期变化。比较展示仍以各项明确信息为主，不合成投资机会分数。

## 6. 从计算到研究

第一版的可选筛选条件为：存在合格的正盈利配对、EPS 上修且对应参考 PE 下降。它是实验入口，不是验证过的投资规则。只发生上修但价格或口径尚未合格的记录进入待补证材料，不能从统计中无声消失。

条件首先作用于机构级配对。公司只要存在命中记录即可进入初步材料，但同时返回该公司所有有效配对的分歧、命中机构数与分母，不能只展示最乐观的一家。需要更严格的公司层面筛选时，另行预先确定覆盖与汇合规则，不混用「至少一家命中」和「整体预期改善」。

具体地，公司命中须存在同一合格机构配对同时满足 `eps_change_pct > 0` 且 `pe_change_pct < 0`。不能从两家机构各取一个有利条件拼接命中；公司层面的中位数仅供展示，不替代这条规则。多数机构下修而单家命中时，只能称「存在机构上修线索」。

该条件可能包含明显下跌的公司，不能统称为「价格变化温和」。展示时区分上涨、下跌与跌幅；若实验确实要研究小幅波动，应在运行前另设双侧价格变化区间。价格剧烈下跌需要调查新的风险，不能仅凭参考 PE 下降认定预期差。

阈值和最少机构覆盖如需设置，在实验前写清。没有合格记录可以返回空结果；`limit` 仅控制展示，保留匹配总数、实际公司数和缺失项。不为了填满名单放宽条件或反复调参。

发现接收计算结果后，围绕以下问题调用研究：预测为什么上修，订单与经营证据是否支持，改善是否持续，是否伴随资本开支、稀释或其他风险，以及价格条件是否合理。先复用已取得研报，再补读公司与关键关联方的原文。

研究需要检验能改变解释的竞争因素，例如一次性资产出售、会计口径调整、基数变化、单一机构的乐观假设或市场对兑现风险的合理担忧。允许排除所有候选；用户要求投资机会时，不能把数值名单直接当作完成。

## 7. 最小实现组织

取数继续使用现有公共门面与批量运行方式，限流、超时、缓存和来源回退仍由数据层统一处理。一次获取研报后复用，不因增加信号入口重复读取同一公司。

新增一个确定性的计算入口，暂定 `research.forecast_price_changes(...)`，公开于现有 `scutio_data.research` 包。它接收已取得、保留身份与来源的预测信封、对应日线信封和明确窗口参数；自身不联网、不设置供应商切换，也不隐式收集整套财报。

建议将窗口配对和计算放在 `research/signals.py`；EPS 字段解析、机构和财年识别、冲突标记继续由 `research/consensus.py` 唯一维护。新旧计算共享有效观测校验，相邻修订与固定窗口比较分别定义，避免复制源字段解析代码。

| 输入/输出 | 最小约定 |
|---|---|
| 输入 | 预测/修订观测信封、匹配证券日线、`start_date`、`end_date`、`fiscal_year`、陈旧度与近零规则 |
| 机构级结果 | 身份、两端预测和原文标识/日期、价格及口径、可计算指标、比较有效性与原因 |
| 公司汇合 | 配对机构数、上修/下修/持平、新增覆盖、另列的未更新数、分歧、合格指标分布、缺口 |
| 外层信封 | 沿用 `ok/error/items/partial`；保留来源、窗口和覆盖；分别统计请求、取数成功、可计算、命中、缺失与展示的对象数，补证状态不能被总体成功覆盖 |

无效身份或混入其他证券拒绝计算；部分记录不合格时保留有效结果和逐项原因；成功取得且无人命中条件与请求失败分别表达。输出只做事实计算与可追溯统计，筛选复用 `screen_records.py`。

准确的可选参数与字段名称在实现时与现有信封统一，本设计中的名称为拟议接口。接口定稿后，调用说明放入现有 toolkit；发现能力只链接用途与边界，不复制公式、字段与脚本参数。

任务内材料复用现有运行时与缓存，不新增自动研究档案或通用持久信号库。用户要求保存研究时仍走现有记录流程；开发数据审计与实验结果进入 `evals/`。将来若要积累历史时点数据，需单独设计来源、版本、存储规模与保留策略。

## 8. 验证与验收

### 8.1 确定性与真实字段检查

实现阶段覆盖以下必要测试：固定窗口与相邻修订区别；同机构重复报告去重；跨财年阻断；同日冲突整组阻断；新增覆盖与未更新；零、负、近零 EPS；缺失和过旧预测；报告日期与可用时间不同；停牌端点缺失；错误证券；拆股或股数口径不明；现金分红与复权价格；部分失败；没有合格候选。

公式使用可人工复核的夹具，至少包含上面的正常例子和会改变结论的异常例子。指标单位明确为数值或百分数，不以测试生成文本或复写公式本身证明正确性。

真实取数先做小样本字段审计，选择具有预测上修、机构分歧、无覆盖、股本变化等不同情况的对象，核对研报原文、日期、EPS、机构身份与行情。选样依据在测试前记录，失败与不能核实的每股口径单列。真实字段审计通过后才扩大样本。

### 8.2 研究增量实验

比较同一版本的发现能力「使用量化线索入口」与「不使用该入口」，保持问题、截止日、模型、工具和资源条件一致，各用新会话。两边都保留其他发现路径，避免把对照限定为新闻摘要。

检查入口是否带来核实成立的新对象、变化或解释，是否减少无效调查，是否因研报覆盖偏差漏掉重要公司，以及最终经营与价格判断是否改善。记录实际取数成本、等待、失败和补证成本。候选数量、冷门程度或格式完整不作为成功标准。

评审匿名比较回答与关键工具轨迹，重大事实错误、范围误报或口径错误单独列为失败。没有新增价值、成本明显增加或扩大遗漏时，也应保留结果，不以已有信号名称为理由宣布通过。

### 8.3 收益预测验证属于后续研究

只有在历史证券范围、预测版本、披露可用时点和公司行动均可核对后，才检验后续收益。先冻结规则、收益窗口和对照，再做跨时期样本外测试，处理行业与规模暴露、重复信号、重叠持有期、退市、停牌及交易约束。

事件后收益相关性与可实施组合收益分开报告；后者还需明确组合构建、成交时点、换手和成本。不用当前已知信息重建过去信号，不把短期涨跌或样本内最优参数作为有效性结论。

第一版验收分为三项：计算与字段正确、能否改善发现研究、是否有收益预测证据。前两项通过也不代表第三项成立。

## 9. 与已有设计的实施关系

先完成发现能力的内容拆分与基础行为检查，再将此入口作为一个独立实验接入；数据字段审计可以提前开展。无需等待全市场公告索引或完整历史数据库才能做当前研究实验。

预计实现影响 `research/consensus.py`、新增 `research/signals.py`、`research/__init__.py`、相关 toolkit 说明与有意义的数据测试；发现说明与 `discover-evals.json` 仅补入口选择和边界用例。避免另建量化 Skill、固定采集工作流或与现有筛选并行的第二套实现。

本设计不替代 [发现能力设计](discovery-design.md)，两者分别维护候选发现方法与量化计算口径。扩展现金流改善、经营拐点或其他信号之前，先记录首个信号对研究的实际增量与局限，再判断是否值得增加接口和维护成本。
