# Scutio「发现」能力设计

状态：设计草案，尚未实现。日期：2026-09-14。现状核对基于提交 `a92149b`。

## 1. 设计决定

将「发现」作为 Scutio 的第六个能力，使用 `references/capabilities/discover.md`。继续保留唯一的 `scutio` 技能入口，由用户问题决定按需加载哪些能力。

发现解决「哪些对象值得投资研究、为什么优先调查它们」，研究解决「这些对象的经营机制、未来状态和价格是否支持判断」。发现负责选择和比较调查对象，并调用研究把重要线索推进为有依据的机会判断。

独立能力的价值在于补足开放式任务的启动、覆盖和候选取舍。新增文件本身不证明发现质量提高；是否采用新版本，要通过实际执行验证。

本轮只交付此设计文档。后续实现首先调整能力说明与评测，再根据实验暴露的缺口补数据入口。完整全市场扫描属于另一个需要验证数据覆盖的目标。

## 2. 能力边界与路由

按用户希望得到的结果路由。公司名、行业名是否出现，不能单独决定能力。

| 用户问题 | 主要入口 | 应完成的工作 |
|---|---|---|
| A 股有哪些值得研究的机会？ | 发现 | 确定起始范围，广泛探索，选择并研究候选 |
| 电网投资增长，哪些公司可能更值得考虑？ | 发现 | 沿投入和受益关系寻找对象，比较经营影响与价格条件 |
| 某公司扩大资本开支，产业链里还有哪些机会？ | 发现 | 从已有公司向外寻找受益对象，核实价值归属 |
| 电网行业未来三年会怎样变化？ | 研究 | 解释产业约束、竞争和未来状态；按需研究具体公司 |
| 如何看待某公司未来三年，当前估值合理吗？ | 研究 | 调查主导未来价值的变化，推演经营路径并连接价格 |
| 比较这三家公司的前景与估值 | 研究 | 对指定对象做同口径研究与比较 |
| 上次更看好甲，新证据是否改变选择？ | 复核 | 检验原判断与选择依据，需要时补研究 |
| 今天 A 股怎么样？ | 按需查证与取数 | 回答市场情况，深度随问题决定 |
| 从这张表筛选符合条件的公司 | 程序筛选，按需查证 | 对给定样本执行条件，不自动升级成机会研究 |

查证、推演和复盘继续承担原有职责。研究保留主动寻找重要变化、追踪关联方和修正研究范围的能力；新发现涉及用户需要的其他投资对象时，可以自然接入发现。发现与研究之间传递已有材料、主张和缺口，避免重新抓取整套数据。

这些能力描述任务职责，不对应固定 Agent、执行顺序或输出模板。

## 3. 发现如何展开

### 3.1 形成起始范围

从上下文识别投资市场、期限、主题和现实约束。已有信息能够支持起步时，说明采用的范围并开始调查。只对会显著改变任务的歧义追问，不要求用户先指定公司或完整论点。

区分投资期限、资料检索窗口、事件发生日和报告期。研究未来三年时，近期披露是入口，早年启动而尚未兑现的项目也可能是重点。固定「近 90 天」仅可作为实验设置，不能成为日常研究的统一限制。

### 3.2 从多个方向产生线索

将宽泛方向改写成可检索的行为和待解释的问题。下表是可选入口，随市场、期限、来源覆盖和新发现调整；不要求每次全部执行。

| 观察方向 | 可调查的变化 | 继续研究的关键问题 |
|---|---|---|
| 资本配置 | 投资预算调整、扩产、收购、研发或人才投入转向 | 资源投向哪里，相对原有业务有多大，回报由谁获得？ |
| 需求与供给 | 采购、部署、交付、订单、交期与产能退出 | 需求是否进入实际行为，短缺和议价权能持续多久？ |
| 技术与经济性 | 商用验证、系统成本下降、替代路线成熟 | 哪些客户开始采用，谁受益，谁的利润可能流失？ |
| 经营与竞争 | 业务结构变化、盈利拐点、现金流改善、份额变化 | 是持续经营变化，还是低基数、周期或一次性因素？ |
| 特殊事项 | 分拆、重组、资产出售、治理与资本分配调整 | 股东拥有的资产、权利、负债和回报路径会怎样改变？ |
| 经营与价格 | 持续兑现的经营表现、估值压缩、悲观预期 | 当前价格要求什么，市场担忧是否有充分依据？ |

结合跨公司结构化数据、披露索引、产业材料与宿主检索，避免单一来源决定候选范围。热门公司可以有新的投资信息，稳定业务也可以进入候选；冷门程度和新闻热度都不作为质量标准。

同一事件的转载合并处理，保留原始披露与后续进展。材料缺少标题关键词时，仍可从关联方行为和正文关系发现线索。

### 3.3 决定哪些分支值得继续

一条线索至少能够解释发生了什么、为什么可能重要、可能影响哪些对象，以及下一步查什么能区分不同解释。这些信息可以用短段落表达，不要求先填完表格才能调查。

按潜在经济影响、证据状态、期限相关性和补证价值安排研究精力。影响大小结合公司业务规模与未来价值判断，不按新闻数量或统一财务阈值打机会分数。影响可能很大但材料尚少的分支，优先定向补证；缺少已兑现利润不构成淘汰新业务的理由。

核实供应、客户、股权和收入归属后，沿关系寻找具体上市主体。关系不实、影响微弱、优势容易被抵消或不符用户范围时，保留原因并收束。主导瓶颈或价值归属发生变化时，允许调整候选范围。

### 3.4 调用研究完成判断

对重要候选使用研究能力，核实经营机制、时间路径、资金要求及当前价格隐含预期。估值方法、多业务价值归属和证据标准继续由研究及共享方法维护，发现文件通过链接引用。

比较候选要说明选择依据：谁可能保留更多经济价值，兑现条件有何差别，价格要求是否合理。研究优先级与投资吸引力分别表达；容易取得材料不等于值得投资，尚未反映在股价中也不能仅凭价格反应推断。

### 3.5 汇合与收束

交付以最重要的机会判断及依据为中心，篇幅和对象数量随证据决定。可以明确有吸引力、吸引力不足，或目前只支持到受益线索这一层；这些是结论强度，不新增固定评级标签。

影响主要结论且仍可查明的缺口继续推进。分支已被排除、关键资料受阻或进一步取证不再改变判断时收束，并说明原因。用户只要求线索时，交付深度相应缩小。

用户要求投资机会时，线索名单不构成完成。能够继续查明的经营与价格缺口应在本轮推进；确因资料受阻只能交付线索时，明确机会判断尚未完成、当前证据支持到哪里，以及具体障碍。

结果应让用户理解为什么研究这些对象、变化如何影响经营、价格要求什么、哪些事实会推翻判断，以及本轮的重要覆盖缺口。可以没有合适机会，不为满足数量保留弱候选。

## 4. 协作与临时材料

继续使用现有 [研究协作](../skills/scutio/references/methods/pipeline.md)。重要、开放式任务在环境支持时并行调查独立问题；先看范围和未知，再决定分工。新发现可以补派、调整或结束分支，不把上述六个观察方向固定成六个角色。

任务示例是「核实新增投入是否已经形成采购」「调查瓶颈缓解后利润留在哪一环」「检查价格要求的增长能否实现」。初步范围不清楚时可以委派探索。主 Agent 负责共享会改变研究方向的发现、对照解释和接回最终判断，不能用多个 Agent 一致同意代替证据。

没有 subagent 的宿主，沿相同问题顺序调查并复用材料。数据接口、检索、等待与失败处理继续使用宿主能力和现有运行时，不引入特定框架或强制编排服务。

本轮材料按需保留来源、时间、完整证券身份、变化、可能影响、证据与解释的区别、关键缺口及取舍原因。它们是任务内的工作信息，不定义新的持久化 schema。已有会话与材料足够时直接复用。

发现不增加自动研究档案、跨会话记忆、后台监控或提醒。原文与接口缓存遵循现有目录；用户要求保存研究时才使用现有复盘和记录流程。开发评测材料保存于 `evals/`，不进入用户研究档案或技能安装包。

## 5. 数据能力与覆盖边界

以下为当前代码与调用文档的核对结果，不代表本设计已重新执行这些金融接口。

| 当前入口 | 可以支持什么 | 需要保留的限制 |
|---|---|---|
| `events.performance_updates(report_date, code=None)` | A 股指定报告期的业绩预告、快报发现 | 仅覆盖有相应披露的数据；报告期不是公告日期；失败与缺失分别披露 |
| `events.company_events(day, code=None)` | A 股按日公司事件摘要 | `discovery_only`，源上限 5000 条；不是完整公告流 |
| `research.industry_reports('*')`、`broker_reports(...)` | 跨公司产业、策略和宏观线索 | 代表供应商覆盖，不能推断未被研报覆盖的公司没有机会 |
| `feeds.telegraph`、`global_news` | 补充跨市场中文资讯线索 | 源窗口分别为 20 / 200 条，不支持宣称覆盖完整历史窗口 |
| `announcements.stock_announcements`、`periodic_reports` | 对候选核实公告与定期报告原文 | 主要按公司调用；市场覆盖与原文解析均有各自限制 |
| 行情、财务、估值、公司行动等公开门面 | 核查候选的经营基础、价格和重要事项 | 大多需要已知证券身份；批量调用不自动建立全市场证券池 |
| `screen_records.py` | 对已取得样本做确定性筛选 | 不建立数据库，不产生机会评分，不证明全市场覆盖 |

数据细节以 [数据索引](../skills/scutio/references/toolkit/index.md)、[事件说明](../skills/scutio/references/toolkit/02-market.md)、[研报说明](../skills/scutio/references/toolkit/04-research.md)、[新闻说明](../skills/scutio/references/toolkit/06-feeds.md) 和 [公告说明](../skills/scutio/references/toolkit/07-announcements.md) 为唯一维护位置。能力文件只引用入口与用途，不再复制完整签名、参数和限流策略。

本轮范围说明应覆盖来源、实际查询窗口、取得与读取范围、涉及对象及缺失或截断情况。接口已经提供的覆盖元数据直接复用，未知覆盖率保持未知。区分证券数、公司数与文章数；同一公司的不同上市证券不能直接计为不同机会。

### 完整全市场扫描需要额外满足什么

广泛跨行业发现可以先使用现有入口和宿主检索开展。要声称对某市场执行了完整扫描，还需验证：

- 可枚举的证券范围、市场身份及截止时点，明确停牌、退市或其他排除范围。
- 对所声明的事件类型和时间窗口具有可核对的索引、分页和截断信息。
- 横截面数据的报告期、披露时点、币种及定义可以比较。
- 可报告实际扫描、解析失败、未取得与未命中的对象；未取得资料不计为未命中。

完整性只能针对具体证券范围、资料类型和时间窗口声明，即使遍历完证券名单，也不等于发现了所有投资机会。抽样复查可用于发现遗漏，不能证明全市场完整覆盖。

后续优先验证证券名单和跨公司公告索引能否稳定取得，再决定是否增加公共门面。数据层继续统一处理 Financial API、AKShare 与现存必要备用来源；配置 Key 不自动承诺跨市场全量数据或无限请求额度。来源未验证前不设计绑定某个供应商的调用流程。

## 7. 验证设计

### 7.1 行为用例

| 场景 | 应观察到的行为 |
|---|---|
| 只给市场与投资期限 | 能产生可调查问题并开始发现，不要求用户先指定公司 |
| 同一产业的前景问法与机会问法 | 分别完成机制研究与对象发现，深度和取舍符合目标 |
| 指定公司扩大投入，寻找产业链机会 | 向外调查真实关系与经济影响，不局限于原公司 |
| 重大变化尚未进入利润，且初始材料稀少 | 沿高影响缺口补证，不因缺少历史盈利直接淘汰 |
| 热门报道很多但受益关系薄弱 | 合并重复来源，核实关联，能够排除候选 |
| 经营稳定、价格要求较低 | 可以研究吸引力，不强加转型或新技术主题 |
| 源被截断、部分市场缺数据 | 说明实际范围并补查关键缺口，不声称全市场没有机会 |
| 合作方材料改变价值归属 | 更新研究对象与结论，主答保留改变判断的发现 |
| 候选均不成立或价格要求过高 | 明确排除原因，不凑数量 |
| 简单行情、事实查数、指定公司研究 | 不被发现能力扩大任务；原有研究深度不退化 |
| 无 subagent 环境 | 仍能完成发现与调查，并如实保留深度或覆盖限制 |

给定材料用例检查推理、路由与汇合，不能证明开放检索能力提高。数据门面测试检查字段与接口，也不能替代模型行为评测。

### 7.2 真实对照实验

第一轮以「A 股中未来 1—3 年值得研究的投资机会」为试验问题，不预置行业或公司答案；可以沿关系补查港美主体，但交付范围与用户要求一致。近 90 天披露可作为初始入口，必要时回溯长期项目。

比较当前版本、候选版本和无 skill 对照。同一轮使用相同模型、推理设置、宿主工具与 subagent 可用性，采用新会话；执行前确定截止日、问题、评审维度与资源条件。评审不看版本标签，也不把任何公司或项目名预设为正确答案。

初轮可采用三个问题：上述无预设对象的 A 股任务、一个由明确产业变化寻找机会的任务、一个未参与方法设计且不以热门新技术为前提的任务。三个版本分别执行，合计九次。问题在执行前冻结；这一规模用于开发诊断，不证明统计稳定性。

资源可设置相同的实验上限，以区分方法收益和额外投入，并记录实际消耗。该上限只用于实验，不能写成日常研究的时间、搜索次数或 Agent 数量限制。输出不要求相同候选数，分别评价研究过的对象、保留下来的对象和合理排除的分支。

保留提示、版本、材料与获取时间、工具轨迹、回答和评审依据。实时资料无法完全一致时披露限制；冻结材料的重放单独标明，历史案例仅使用当时可得信息。

| 维度 | 判断依据 |
|---|---|
| 发现增量 | 相对对照，是否多找到核实成立的重要变化、受益关系或新的有效解释 |
| 事实与口径 | 身份、日期、原文关系、字段、币种和计算是否正确；关键事实错误单独列为失败 |
| 经济机制 | 是否解释影响规模、利润归属、竞争抵消与兑现条件 |
| 价格连接 | 是否检验当前价格要求，避免将可能受益直接称为便宜 |
| 覆盖诚实性 | 是否区分读取范围与市场范围，处理截断、失败及来源偏差 |
| 推进与汇合 | 是否追查关键缺口，并把足以改变结论的发现纳入主答 |
| 效率与退化 | 每项有效发现的资源消耗、无效重复，以及指定对象研究是否受损 |

对照之外，从不同行业、规模和资料关注度抽样复查同期披露，检查主流程漏掉哪些重要变化。抽样只能提供遗漏诊断，不推断全市场召回率。短期涨跌、候选冷门程度、篇幅和 Agent 数量均不作为成功标准。

由两位独立评审匿名核查并交换版本展示顺序，分别比较候选版与两个对照。单题判为有明确增益，需要双方都能指出新增且核实成立的重要发现、经济解释或价格判断，同时候选版没有重大事实错误或范围误报；分歧和明显取舍记为无明确优势。遗漏扣分需证明材料在截止日前可得、与任务相关且可能改变判断。整体采用决定参考跨题结果与研究退化检查，不靠一题胜出或平均分掩盖重大错误。

完成首轮后，在不同产业背景和不同提示下复测，关注增量是否重复出现；条件允许时补一次无 subagent 或另一宿主的执行。若改善只来自增加检索量、只出现在一个主题或出现研究退化，保留结果并继续调整，不宣布能力已稳定提升。

## 8. 实施与验收顺序

1. 按内容归属新增发现说明，迁移现有段落并更新入口。静态检查链接、按需加载、安装包包含新增能力文件且排除开发设计与评测；不以精确措辞断言代替行为验证。
2. 新增行为用例并运行定向路由、前瞻研究、价格判断和失败处理检查。针对重复、过度流程化或研究退化修订说明。
3. 执行真实对照和遗漏复查，保存实际结果，区分方法问题与数据入口问题。
4. 对证实阻碍发现的入口做单独数据设计，优先验证证券范围和跨公司披露索引。接口变更需要真实字段核验和相应代码测试，再复测发现效果。

能力拆分的验收是职责清楚、内容单处维护、按目标路由且原有研究未退化；发现效果的验收依赖真实对照；完整市场覆盖的验收依赖证券与来源范围证明。三者分别报告。
