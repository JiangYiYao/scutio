# 研究重点与期限推演：方法优化与验证

日期：2026-09-10。

这轮从用户正在试用的 v2 修改研究方法。关注研究重心、期限内事件与公司变化、重要发现汇合，不以更乐观的结论或特定项目名作为改进目标。最终六份技能文件净增 1,174 个字符，仍是一套运行方法；实验版本仅作为冻结材料保存。

## 方法改动

| 位置 | 决策上的变化 |
|---|---|
| [入口](../../skills/scutio/SKILL.md) | 前景研究的完成标准包含用户期限内可能达到的状态和路径 |
| [研究](../../skills/scutio/references/capabilities/research.md) | 按最影响未来价值且未解释清楚的问题分配深度；新方向分析成功与失效机制，成熟业务分析持续贡献；重要发现接到主张、条件或边界 |
| [协作](../../skills/scutio/references/methods/pipeline.md) | 初步了解研究对象后按问题分工，重大新发现及时返回并调整优先级，汇合与研究完成标准使用同一处定义 |
| [期限](../../skills/scutio/references/methods/milestones.md) | 期限改变事件调查与依赖推演，允许依据公开线索研究公司范围变化；区分期限内经营与对期限后回报的验证 |
| [推演](../../skills/scutio/references/capabilities/simulate.md) | 期末价值可反映更远期现金流；资金投入、交易条件及稀释接到现有股东回报 |
| [证据](../../skills/scutio/references/methods/evidence-and-sources.md) | 重要未完成项目继续查截至研究时点的更新，早期条款未定不能直接当作当前状态 |

独立方法审阅修正了三处过强要求：现有利润仍可合理主导成熟公司研究，证据可以确认原判断，未来状态必须从调查推演而来。没有固化业务角色、并购情景、三阶段或精确概率。

README、设计和 ADR 同步当前职责。行为用例更新五条、新增一条非 AI/航天案例；仓库共 62 条用例定义，不代表本轮执行了 62 条。

## 封闭资料对照

两个虚构公司、三个自然问题，每个问题分别用修改前后方法在独立上下文执行，共六次试答。澄川水务同时有成熟设备和高投入的新型回用系统，公开材料给出试验、采购、合作方式及 2027—2031 年节点；另用平禾包装检验没有重大转型的成熟业务。评分与资料在执行前冻结，执行者未收到期望结论或评分。

每个执行者只用分配的资料与方法，可做计算，不联网、不再委派。该设计检验材料组织与推演，不检验开放发现或多 Agent 协作。全部执行沿用宿主设置、未设置模型或思考覆盖；接口未提供可独立核验的精确配置与 token 用量。方法摘要经复核与冻结版本一致，工具操作保存为执行者记录的摘要，并非完整宿主轨迹。

匿名评审只读取夹具、冻结规则和 A/B 回答，完成评分后才由主任务对照映射：A 为修改前，B 为修改后。结果：

| 问题 | 观察 |
|---|---|
| 澄川整体看法 | 无明确优势；两版均围绕新业务的需求、成本、合作责任和股东回报展开 |
| 澄川未来三年 | 无明确总体优势；新版更直接解释 2029 年经营形态及三年内验证对 2031 年以后回报的意义，旧版对约束转移和必要依赖校准更细 |
| 平禾未来三年 | 两版负控均通过；均围绕价格传导、维修更新与分红，没有无据引入新赛道或资本交易 |

未发现实质数字或事实错误。主案例均达到粗分档的 12/12，负控适用项均为 10/10；这是该资料包及量表出现上限效应，不能解释成研究完美或方法等效得到证明。新增任意估值倍数的条件计算没有被当作比较优势。

全部原始回答、夹具、评分引文、方法快照及 SHA 保存在同名 JSON 中。给定材料下的局部改善尚不能证明真实研究稳定提升，也没有进行无 skill 对照。

## 首轮完整 SpaceX 试答

使用首轮修改后的冻结方法，给新上下文仅提供“你怎么看未来3年的SpaceX”、研究时点和技能路径，未给 Terafab、Tesla 或预期结论。允许公开网络和原生子任务，不设固定检索配额。

实测耗时约 21 分 26 秒。主研究 16 次 web 调用、技术子任务 13 次、资本子任务 17 次，共 46 次；每次可包含多个查询、打开或查找，不能混作搜索次数。两个子任务均完成；另一次星链委派因共享并发槽位不足未启动，由主研究承担。主研究与此前真实用户任务的用时和环境不同，不能据此作版本因果比较。

已看到的改进：

- AI 被明确写成决定整体价值的更大变量，地面算力、Cursor 应用、供应商响应和轨道计算有具体路径。
- 将算力合同 2029 年 5 月到期与用户 2029 年 9 月终点连接，期限改变了对续约及设备回收的分析。
- 将首批轨道能力、运输规模和更长期低成本经营分开，并吸收了子任务的具体发现。

仍未通过本轮想解决的开放研究回归：

- 最终回答没有纳入 Tesla 合并情景，已保存请求中未见针对该情景的专项调查。
- Terafab 只用于解释首代部署对自建芯片路线依赖较小；未把近期项目投资进展接入公司整体前景。提到名字不能算完成相关研究。
- 主研究 20 项搜索中有 18 项写成 `site.domain`，未实现预期的域名过滤。部分查询仍返回了有效来源，不能说这些查询全部失败；但这是已有 `verify.md` 正确规则仍未稳定执行。
- 2029 年收入的任意条件算术仍只是估值敏感性，没有替代经营与估值之间的完整论证。

没有据此宣称发现能力已稳定改善，也没有把更多调用或更多子任务记为质量胜出。

## 实测后的最后修补

初步取证补充调查公司及关键关联方仍在推进、讨论的重大事项，用披露、战略访谈和可靠报道校准范围；不把已完成交易当作未来公司范围的上限。证据方法补充更新已发现的重要未完成项目，再判断进度和相关性。

曾在证据方法增加检索语法说明，审阅发现 `verify.md` 已有同一规则，最终删除重复段并保留唯一原定义。语法执行问题如实保留为未解决的稳定性问题，不以重复写规则作为修复证明。

同名 JSON 区分 `before`、首轮 `after`、用于范围检查的 `final` 和去重后的 `installed-final`。首轮六次封闭试答及完整 SpaceX 试答均使用 `after`，不能追认成最后修补已得到全流程验证。`final` 到 `installed-final` 仅移除上述重复语法段，研究范围和旧项目更新要求相同。

## 最后一次初步发现检查

用新的独立上下文加载 `final`，请求改为“你怎么看未来三年的SpaceX？请先做初步调查，给出最值得进一步深挖的问题和公开依据，暂不写完整公司报告。”没有给项目、交易对手或期望结论，不允许继续委派。该检查执行了 10 次 web 调用，包含 22 项搜索请求；有一次 JavaScript 语法错误在请求发出前被修正。逐次请求没有可信时间戳，保留实际顺序与收集结束时间，不倒填。

这次初查把地面 AI 合同回报和资本用途排在前面，并自行调查到：

- Terafab 的 8 月更新与 Louisiana 新基地规划，明确区分共同投入、总规划、三年付款节奏及 SpaceX 承担比例，没有仅列项目名。Terafab 动态官网未能直接读取，使用检索缓存并标注限制。
- Tesla 潜在合并的报道及 Musk 对中国业务拆分报道的否认，将进一步重组与维持合作并列为待检验情景，没有把交易当作已启动或给出精确概率。尚未核对完整交易文件集合，不能据此声称不存在交易。
- Cursor 已完成收购及后续模型供应变化，以及 EchoStar 频谱信托移转和最终交割的区别，重要旧线索得到状态更新。

这支持“本次初步调查能主动发现相关变化并提出有依据的问题”。它不证明完整研究能完成路径、估值与最终汇合，也不能证明增加的两条规则造成了结果：请求已改为只做初查，没有同题旧版对照，仍是同一开发案例的一次执行。

检索语法仍有一项 `site.spacex.com` 写法，之后出现正确的 `site:spacex.com` 查询。说明本次能够继续修正，不能据此声称语法稳定性已解决。对于 Reuters 报道，否认的对象应严格限定为所报道的中国业务拆分安排，不应概括成否认所有可能的合并。
