# 2026-09-12 Windows 升级验收

从 `v0.1.0-alpha.1` 升级到 `v0.1.0-alpha.2`，再升级到当前未提交候选的主要路径通过。研究记录、配置、缓存、原文及附件在每次安装前后均保持字节一致；升级后的代码可以追加旧研究记录。另发现并修复了 requirements 中文注释在旧 pip / Windows GBK 环境中的解码错误。

步骤退出码、耗时、文件哈希、各版 skill 文件指纹、旧记录读回和最终运行环境见[审计 JSON](2026-09-12-windows-upgrade.json)。未修改正式版本号、提交代码或更新实际宿主安装。

## 测试环境

Windows、Python 3.12.9，实际执行各历史标签和当前工作区的 `install.ps1 -Mode copy -WithVenv`。技能、Python 环境、用户数据均在独立测试目录，目录名含空格和中文。候选以 `400b52611350b5ae7eb47b7b2f8a1251ac4af610` 工作区为基础，包含之前的编码和锁修复及本轮 requirements 编码声明。

旧版通过本地 Git 标签恢复源码，按今天可解析到的依赖建立真实 venv；不是复原当时发行包的完整约束环境。使用虚构中文研究记录、虚构凭据和 `public` 数据偏好，不读取真实 Key 或个人研究目录。

|---|---|
| alpha.1 在 `PYTHONUTF8=0` 下首次安装 | 重现 `UnicodeDecodeError`；pip 将 UTF-8 requirements 的中文注释按 cp936 解码。未成功安装技能，新建环境被清理。 |
| 建立可用 alpha.1 安装 | 使用 `PYTHONUTF8=1` 安装旧版，并用旧版 CLI 创建研究记录、配置及偏好。 |
| alpha.1 → alpha.2，`PYTHONUTF8=0` | 重现同一 pip 解码错误；10 个原有用户文件保持一致。 |
| alpha.1 → alpha.2，`PYTHONUTF8=1` | 升级成功，安装内容与 alpha.2 源码一致；10 个原有用户文件保持一致。 |
| alpha.2 → 当前候选，`PYTHONUTF8=0` | 编码修复后直接升级成功，用户文件完整、原 venv 标记保留，安装内容与候选一致。 |
| 同一候选重复安装 | 成功，用户文件和原环境标记保持一致，无残留安装 staging。 |
| 新代码追加旧记录 | 中文原话完全相同；原创建事件及初始快照保持不变，新事件追加成功，Markdown 同步包含修订。 |
| 现有 venv 的依赖解析失败 | 离线注入不存在的包；旧 skill、用户文件、Python 可执行文件与环境标记保持不变，旧安装探针仍 `ready`。 |
| `-RecreateVenv` 依赖解析失败 | 新环境安装失败后恢复旧环境，用户文件和旧 skill 保留，无遗留 backup/staging；探针仍 `ready`。 |
| `-RecreateVenv` 成功 | 用户数据保持完整；新环境通过探针，旧环境同级备份及原标记仍保留。 |
| 重建后的实际数据调用 | 从安装目录导入，通过新 venv 获取茅台、腾讯、苹果公开报价；配置、研究记录及保存原文未被改写。 |

10 个原有用户文件覆盖记录 JSON/Markdown、研究附件、虚构凭据、数据源偏好、配置/记录锁、API 缓存、原文及状态文件。用户明确要求追加记录后，记录 JSON/Markdown 的正常变化单独核对，不要求它们仍等同追加前字节。联网取数后允许产生新的缓存和运行状态，配置、研究记录和保存原文继续保持不变。

失败注入采用 `PIP_NO_INDEX=1`：已有环境缺少最后添加的测试包；重建的新环境缺少第一项运行依赖。两者均确实到达 pip 依赖解析阶段。测试器最初错误地要求两种失败都包含同一个测试包名，随后修正并继续验收，未将该断言错误算作安装器失败。

## 本轮修改与回归

运行时和开发测试的 `requirements.txt` 首行增加 `# coding: utf-8`，使 pip 明确按 UTF-8 读取。未通过强制开启宿主全局 UTF-8 模式掩盖问题，也未调整依赖版本范围。

- `test_requirements_encoding.py`：两个 requirements 文件在模拟 cp936 的 pip 解码入口中保持原始 UTF-8 内容，兼容 Windows 非 UTF-8 测试进程。
- `test_upgrade.py`：普通配置目录和外置配置目录两种情况，重复覆盖安装后用户文件不变，旧安装残留文件移除，新代码继续追加原记录。
- 本轮定向回归连同现有安装测试：**25 通过，38.30 秒**。`ruff check`、`ruff format --check` 通过；上轮全量 1058 通过的结果仍属于上轮快照，本轮未将其冒充新的全量运行。

## 验收边界

本轮可确认“停止使用后的源码复制安装升级”以及依赖解析失败保护。没有模拟断电、强杀、磁盘满、杀毒软件锁文件、宿主正在执行时覆盖安装，或不同操作系统。已有 venv 的 pip 中途改包失败没有事务回滚保证；本轮失败发生在解析阶段，不能泛化为任意安装失败都能恢复环境。需要重建时，`-RecreateVenv` 的旧环境备份和失败恢复路径已实际验证。

升级前应结束正在运行的 Scutio 任务；升级后重新加载技能或重启宿主，使说明和执行代码来自同一版本。技能目录内的个人修改仍会被覆盖，用户数据应按约定保存在独立数据目录。
