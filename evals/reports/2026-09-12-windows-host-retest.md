## 代码回归与修复

`PYTHONUTF8=0` 下首次全量离线回归：**1052 通过、3 失败、1 跳过、13 个 live 用例排除**。两项失败来自测试将 Windows 环境变量键名当作区分大小写；另一项是记录首次并发创建偶发 `Permission denied`。

独立复现中，第 4 次双进程创建出现该权限错误。原因是两个进程可能同时认定锁文件为空，其中一个进程已加锁后，另一个仍尝试写入初始化字节。记录锁、配置锁和维护锁均移除这个加锁前写入；直接锁定空文件的字节范围。[Microsoft `_locking` 文档](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170)明确支持锁定 EOF 之后的字节。

新增三个 Windows 跨进程回归：父进程先锁定空文件，记录/配置操作必须等待并在释放后成功，非阻塞维护操作必须返回忙。修复后的双进程创建另连续通过 60 次。代理测试改为按不区分大小写核对键名，仍验证重试移除代理且未改变父进程环境。

最终全量离线回归：**1058 通过、1 跳过、13 个 live 用例排除，66.54 秒**。`ruff check`、`ruff format --check` 及 `git diff --check` 通过。此前的 UTF-8 文件/子进程修复和 Windows 非 UTF-8 CI 步骤仍保留。本轮未在 macOS/Linux 执行测试，跨平台结果应由 CI 继续验证。

以上判断依据预先固定的核心要求：不把局部证据扩展成整体事实、不把接口失败当空数据、不把未来里程碑当作已经逾期、保留原话和历史、输出与实际数据一致。两个离线夹具过于简单，不能替代开放研究或严谨的盲评。

Grok 执行类首轮也存在测试器错误：`write_file` 不是该版本支持的工具名，使工具白名单退回完整工具集；PowerShell 变量赋值与调用运算符在无交互权限模式下被取消。两个进程均以退出码 0 结束，但 `stopReason=cancelled`，没有完成任务，已单独保留为失败尝试。更正实际工具 ID，并仅授权现有 Python 的直接调用后，使用新目录重跑成功。验收不能只看进程退出码。

OpenCode 参考文档重试的目录授权曾被自动审批拒绝，原因是可能发送私有内容。随后通过公开 GitHub tree 与本地 Git blob 哈希核对，确认 `references/` 下 22 份文档全部与上述公开提交一致；将读取许可仅限该公开文档目录后，审批通过并完成重试。没有放开未提交脚本或其他目录。
