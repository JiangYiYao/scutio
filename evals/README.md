# Scutio 行为评测（开发用）

所有用例针对唯一入口 `scutio`，按能力分文件；评测不进入 skill 安装目录。

用例保存在 `scutio/`，已执行的评测报告保存在 `reports/`。用例定义与运行结果分别维护。

[2026-09-11 取数与字段验收](reports/2026-09-11-data-acceptance.md)另记录数据层真实验证，包含 62 个公开入口的用例矩阵及字段限制；它不是模型行为评测，不用于证明研究能力。

[2026-09-12 Windows 与宿主复测](reports/2026-09-12-windows-host-retest.md)记录 Grok Build CLI 与本机 OpenCode 桌面版服务的实际执行、小规模有/无 skill 对照、记录与行情工具验收，以及 Windows 并发锁修复。保留未触发技能、权限配置错误、模型推理错误和网络失败。

| 文件 | 验证内容 |
|---|---|
| `scutio/evals.json` | 总入口、行情触发、按需加载、问题识别与跨会话授权 |
| `scutio/toolkit-evals.json` | 取数、信封、数据边界与降级 |
| `scutio/verify-evals.json` | 出处是否支持说法、期间冲突与历史可知性 |
| `scutio/research-evals.json` | 未来价值与研究重点、期限内事件与公司变化、业务关系及瓶颈、价值归属与价格条件、会计与增长归因 |
| `scutio/simulate-evals.json` | 用户假设、可核对计算、现金流归属、科目重叠与条件边界 |
| `scutio/review-evals.json` | 命题范围、证据支持的层级，以及支持、推翻、未解决与不相关的新信息 |
| `scutio/reflect-evals.json` | 研究记录、AI 错误、历史依据与修订 |

每条提供用户口吻的 `prompt` 和 `expected_output`。将请求交给仅安装 `scutio` 的 Agent，对照期望检查回答与工具轨迹。标有“虚构夹具，不联网”的案例仅使用给定材料，可以固定信息输入检验判断；真实证券案例需要保留所用材料和获取时点。

`market-overview-trigger` 从仅暴露技能名称和 description 的新会话开始，不预读正文、不在提示中点名 Scutio；记录是否实际加载及随后取数的轨迹。冻结执行日期、交易时段与模拟行情结果，可以在不联网的情况下检查触发和时点处理。

`history-*` 使用虚构的会话工具与材料，不访问评测者真实历史，不联网。各案例当前会话均无旧研究正文，前置条件如下：

| 用例 | 夹具条件 |
|---|---|
| `history-permission` | 检索工具可用，但用户尚未同意访问其他会话；记录同意前是否发生工具调用 |
| `history-authorized` | 研究时点为 2026-09-11；检索只返回 2026-08-10 的澄川水务任务。正文含用户“验收可能顺利”的观点、AI 对资金需求的推断、截至当日的未验收状态与待核实事项 |
| `history-ambiguous` | 检索返回 2026-08-10“澄川水务客户验收”和 2026-08-22“澄川水务估值”，摘要均可能匹配；用户尚未选择 |
| `history-unavailable` | 无会话检索或读取工具，也未提供历史片段 |

这些新增用例是待执行的回归定义；JSON 结构检查通过不代表触发、授权或研究行为已经通过。

## 如何比较改动前后

使用相同模型、思考设置和材料，分别加载两个版本，每个案例使用新对话。依赖“刚才”或“上次”的案例由评测者提供同一份前置对话；记录写入案例使用临时 `SCUTIO_HOME`。每次保存版本、提示、输入材料、回答、工具调用与评分依据，避免把模型变化或新增资料误当成重构效果。

检验 skill 是否有增量时，另设不加载任何 skill 的对照；只比较两个 skill 版本不能回答这个问题。开放研究应在执行前冻结请求、候选内容、工具预算、评分与胜出条件，使用新上下文和跨行业案例，并让独立评审匿名比较。记录检索失败与资料时点；实时网页无法完全固定时，保留这一限制。机会研究另看是否发现重要关系、形成机会命题、推进前瞻推理、查验反证及连接价格，不能仅用格式完整或财务指标数量代替。

比较整体看法与明确期限的问法时，检查期限是否实际影响事件调查、依赖关系和期末公司状态；相同结论或相同项目名不自动表示没有增量，整体版也可能已完成充分推演。用成熟且没有重大转型线索的案例检查是否无依据地强加新赛道或资本交易。给定材料的试答只能检验材料组织与判断，不能证明开放检索或跨 Agent 汇总已改善。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 回答问题 | 偏题或被固定流程阻断 | 部分回答，重点含糊 | 回答核心问题且深度合适 |
| 证据与判断 | 编造或证据不支持结论 | 有依据但关键推断不清 | 判断明确，可逐项检查其依据和边界 |
| 不确定性 | 把未知当否定/等待，或条件当事实 | 表述有边界但混淆关键层级 | 区分事实、解释、假设及取舍 |
| 工具与记录 | 越过范围、掩盖失败或改写历史 | 部分多余取数/缺失标注 | 按问题取证、披露覆盖并保留历史 |

逐项给分并引用具体回答或调用作为依据。数据编造、未授权写入或历史改写需单独列为失败，不能被总分抵消。不会使用工具的纯讨论案例，最后一项记为不适用。

机械中立应在证据明确支持或推翻某解释的案例中观察：统计是否给出相应局部判断。不要把“看多比例更高”当作改善目标。也要检查未解决案例是否保留了不确定性，以及筛选与线索是否被包装成投资排名。

这些是人工或评测运行器使用的行为用例，不会在 pytest、self_check 或 install 时自动执行。代码契约由 `tests/` 验证，真实数据通路由该目录的 `self_check.py` 探测，三者不能互相替代。
