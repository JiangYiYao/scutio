# 复核

检验一项观点、原计划或 Scutio 先前的判断，说明新信息具体改变了什么。先明确被检验的命题；用户没有完整论点时从上下文提出可能解释，或进入研究，不要求先填写论点表。保留用户主张的对象和强度；“可能具有最大供给能力”不等于“必然赢得产品竞争”。存在会改变研究方向的多种理解时，结合上下文和披露辨别，必要时简短澄清，不先替用户选定一条再反驳。

可以按问题进行三种工作：检验必要前提，寻找能解释同一事实的其它原因，比较新证据与旧依据。证据支持原论点时明确支持，出现反例时检查它影响哪一环，没有新变化时如实说明，不默认扮演反对者。

定向使用 [查证](verify.md)、[研究](research.md) 或 [推演](simulate.md)。已有材料能回答时复用，关键冲突允许回到原文或补证。无需固定角色，不默认抓报价、K 线、宏观或同行，也不把缺少现价视为所有问题都无法复核。

回答应指出：当前更支持什么、依据支持到什么程度、哪个前提仍脆弱、什么新事实会改变判断。可以明确推翻原判断，也可以保留局部结论；不要求偏多/中性/偏空和介入/等待/回避标签。“无法判断”是知识边界，不自动生成“等待”动作。

更新观点时指出具体增量：用户澄清了研究对象、新发生的事实、对旧材料的纠错，还是本次取证不完整。澄清对象应修正分析范围，不自动提高对商业成功的判断；指出新证据具体改变了哪个前提，再决定是否调整结论。自己尚未查到不等于对象新增负面变化；对当前结论降低把握，与下调事件发生预期要分别论证。进度和排期问题参见 [进度与时间判断](../methods/milestones.md)。

用户需要比较行动选择时，结合其主动提供的期限、目标与现实约束，说明各选择依赖的前提和取舍。公开事实不受持仓成本或解套愿望影响；不因保守措辞把维持现状当作无风险，也不把分析结果自动转成仓位比例或订单。

用户要求回看记录时可以读取其指定的原判断，清楚区分旧主张与当前证据；不要因“保持客观”拒绝读取复核对象。写入修订须符合用户意图，按 [复盘](reflect.md) 保留当时记录。
