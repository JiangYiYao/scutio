# 研究

从公司与产业变化中形成前瞻判断，并把值得追踪的线索研究为有依据的投资机会。用户可以只给公司、主题或疑问；不要求先有论点、持仓或完整报告大纲。问题只涉及一个经营现象时，解释到所需层级即可。

## 找到值得检验的主张

公司整体研究先辨认当前价值来源、资源正投向哪里，以及哪些变化可能重塑公司。结合经营披露、资本与人才配置、战略、产品和客户行为，选择最影响未来价值且尚未解释清楚的问题深挖；不要只按现有利润、资料丰富程度或熟悉的业务标签分配注意力。重大投入说明需要解释其用途与回报路径，不直接说明投资有吸引力。

初步取证同时调查已发生的业务变化和仍在推进、讨论的重大事项，交叉查看公司与关键关联方的披露、战略访谈和可靠报道。用这些材料校准研究范围，不能只围绕预先熟悉的业务名称和财务指标检索，也不能把已完成交易当作未来公司范围的上限。

把发现推进成具体主张：变化发生在哪一环，什么约束正在被改变，谁可能因此受益，价值通过什么路径和时间传导。对关键变化提出可竞争的解释，再找能区分它们的证据；例如扩产可能是在满足新增需求，也可能只是在替换旧产能。未盈利的新方向要研究成功路径与失效机制，成熟业务要研究可持续贡献与增长约束，按证据形成倾向，不等到全部兑现才判断。

用户给出期限时，用它选择调查事件、梳理依赖关系并推演届时的公司状态，按 [进度与时间判断](../methods/milestones.md) 展开；不只给当前业务概述加上年份。新发现改变价值来源时，重新组织主张和研究重点。

财报用于核对经营基础、会计口径、资金约束及回报，按 [财务与经营分析](../methods/financial-analysis.md) 处理。前瞻证据还包括客户采购与部署、产品交付和实际使用、供应商交期及扩产、技术验证、竞争者响应与政策执行。选择能改变当前主张的材料，不默认收齐一套指标。

## 从分散信息中发现联系

围绕同一机制对照不同参与者的行为，优先追踪时间差、矛盾和尚未解释的变化：

| 观察方向 | 值得继续调查的关系 |
|---|---|
| 需求与部署 | 客户说要投入，是否已经采购、部署或续约？需求扩大先受哪个环节约束？ |
| 供给与瓶颈 | 交期、产能和成本如何变化，短缺是否会被扩产、替代或客户自制缓解？ |
| 技术与经济性 | 改善能否转为客户可用的结果？模块进步对整套系统的成本、吞吐或可靠性贡献多大？ |
| 竞争与价值归属 | 谁拥有客户、稀缺能力和议价权？收益由供应商、平台、客户还是合作方保留？ |
| 时间与市场认识 | 经营变化何时进入收入和现金，现有价格或公开预测要求怎样的兑现程度？ |

追踪原文中的重要业务关系，不只摘取数字。跨公司合作需核实股权、供货、收入归属或合同安排，共同参与一个项目不等于分享全部价值。供应商与客户的材料可以相互检验，多篇转述同一发布会不能视为独立佐证。招聘、专利和设计目标可定位调查方向，其含义需结合后续行为判断。

## 沿关键关系继续取证

对最有可能改变结论的缺口选择下一步：查看原文相邻章节、追到客户或供应商、比较替代路线，或做条件计算。说法矛盾时查清口径或事实差异；只证实一个模块时继续检查它与交付结果之间的关键依赖。优先解决影响大的未知，减少只补背景的搜索。

研究多环节系统时，把资源供给、制造部署、客户使用与回报连起来，找出主导约束及其转移条件。既检查单项改善会不会被其它环节抵消，也判断已有技术、客户和产业能力能支持多大程度的前瞻推断。战略目标、技术验证、单位经济性与规模化回报对应不同证据，但后一步尚未发生不妨碍分析它的可行路径。

参数足够时按 [推演](simulate.md) 比较差距、敏感变量或跨过基线所需的条件；假设从哪里来、哪些会一起变化应清楚。数据不足时用关系、可比案例和有依据的范围推进，不能为算出目标价补造参数。

## 从受益线索到投资机会

用户要求寻找机会时，先确定与其主题、市场和期限相符的有限范围；上下文不够时说明一个合理的起始范围，关键歧义再问。沿证据最强、经济影响较大且可以继续调查的分支，主动核实具体公司及受益程度。无需用户逐个授权候选研究；关系不实、影响太小、优势易被抵消或不符用户范围时，说明原因并停止该分支。

比较候选时解释谁更可能保留价值、为何在当前条件下更有吸引力，而不只罗列相关公司。程序条件筛选按 [筛选说明](../toolkit/screening.md) 执行，筛选结果只是输入；热榜、概念归属或跌幅不自动证明受益。调查过的有限对象不能冒充全市场排名。

把经营前景接到价格：核对市场身份、时点与估值口径，选择与该机制相符的比较或估值关系，判断当前价格要求哪些增长、利润率、再投资和兑现时间。多业务公司的既有贡献与未来增量需接回同一估值，不能用某块业务的优秀证明整体便宜，也不能只凭当前利润否定新方向。可以反推需要达到的条件，再与已查证的路径比较；现有报价或一致预期不足以证明“市场没发现”，价格缺失也不使前面的经营判断无效。

机会判断应能解释为什么是这个对象、为什么现在值得考虑、回报依赖什么条件，以及什么会推翻它。若只证明了可能受益，就明确支持到这一层，并继续补最影响机会判断的证据；若价格已要求过强兑现或核心机制不成立，可以明确判断吸引力不足。无需为了交付数量而保留弱候选。

## 收束与表达

先给本轮最重要的判断或发现，围绕主导未来价值的变化解释路径与分歧，不按业务逐项平均介绍。关键发现应接到主张、推演条件或结论边界，说明支持、修正或排除了什么；仅列出项目名或在结尾提醒验证不算完成分析。成稿前对照已取得的重要发现，检查压缩后是否丢失改变价值来源、时间或归属的关系；未采用的关键线索应有证据或问题范围上的取舍理由。篇幅和情景数量服务问题，不默认完整公司报告、固定风险清单或目标价。

事实解释完成不等于机会研究完成。关键线索可继续核实时，把调查做下去；分支已被证据排除、关键资料暂不可得、或继续取证不再改变判断时收束，保留原因。可以没有值得推荐的机会，但应让用户知道研究排除了什么、确认了什么，而不以“需要验证成本、需求和进度”代替结果。用户只问下一步查什么时直接给问题即可。

按问题选择 [数据接口](../toolkit/index.md)，多个独立请求可用 [批量调用](../toolkit/01-runtime.md#批量调用)。证据与假设记录沿用 [证据与来源](../methods/evidence-and-sources.md)，已有主张转 [复核](review.md)，独立子问题按 [协作方式](../methods/pipeline.md) 分工。用户要求文件时保存结果；只有要求保存研究记录时才按 [复盘](reflect.md) 写个人档案。
