# 围绕问题协作

重要或复杂的开放式研究，环境支持时默认由多个 subagent 并行调查不同方向，主 Agent 负责确定范围、连接发现和形成判断。简单查数、概念解释或给定材料内的直接计算由主 Agent 完成。人数随可独立调查的关键问题和新发现调整；依赖前一步结果的问题继续沿原任务推进，不把五种能力各开成一个角色。

这类研究优先保证覆盖与深度。用户没有另设时间或费用限制时，不用固定搜索次数、轮数或人数作为收束条件；评测中的工具配额不作为日常研究限制。继续投入应针对尚可能改变判断的缺口，重复搜索同一批材料不等于推进。

主 Agent 先形成对研究对象变化和关键未知的初步理解，再按问题分工；范围本身不清楚时，可以委派探索，不必先查齐资料。发现新的价值来源或跨业务依赖后，调整优先级并补派或收束任务，不受首次业务划分限制。

合适的分工是“核实客户是否已采购和部署”“调查瓶颈缓解后利润会留在哪一环”“检验当前价格要求的增长是否可行”；只给业务名称容易让任务退化为概述。每个任务应包含：

- 用户真正要解决的问题与该子问题的关系；
- 对象、截止时点、相关原文或已有材料；
- 需要区分的解释、允许补证的范围、已查过的内容；
- 需要交回的发现、证据、冲突及仍未解决的事项，以及它们对主任务判断或时间条件的影响。

独立核查时不给出希望对方支持的结论，也不把用户的解套愿望作为证据。问题所需的期限与约束可以传入。环境支持时独立任务用新上下文；延续同一子问题可以继续原任务，不建立固定角色流水线。

取数遵循包内限流与复用规则。分工前说明谁负责哪些材料，避免重复抓取。定向补证可以由研究者完成；需要超出约定范围时返回缺口，由主 Agent 判断是否值得继续。

小任务可以直接返回简短发现。已有落盘任务可写自己的材料文件并返回路径，避免长材料重复搬运；不强制每次建立 run 和多份备忘。文件写入后允许检查和修正，保留引用事实与观察时点。

会改变研究范围、主张或期限的发现应及时返回，让其它调查能据此调整。主 Agent 汇合时比较解释而不投票；已有关键发现按 [研究的收束与表达](../capabilities/research.md#收束与表达) 接入判断，尚未解决的高影响缺口继续调查。初始分工共同遗漏重要方向或关键来源读取失败时，可改查合作方、客户、监管与政府原始披露；关键冲突需打开原文或追问对应调查。已启动的任务应完成或明确取消后再结束，不以所有任务已返回代替研究完成。

对耗时检索同样按关键性安排：能够改变主要结论的缺口值得等待或换取证方式，补充背景不应长期阻塞回答。查询挂起时使用工具支持的有界等待或取消，保留未取得的部分；没有新输出时避免密集轮询或重复声称“正在核实”。
